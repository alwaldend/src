## Context

Core is merged with public Mermaid graph integration, strict TypeScript,
theme bundles, physical geometry bounds, depth fitting, and saved camera views.
The complete typed snapshot exporter and raster acceptance were preserved
before the core split. Only their snapshot delta is extracted here.

## Goals / Non-Goals

Deliver offline images from the actual viewer canvas and use them in existing
documentation. Preserve the current graph model and camera/framing ownership.
Parser replacement, sequence support, dependencies, and deployment are outside scope.

## Decisions

- Reuse the preserved exporter, Bazel rule, and image E2E. Replace its sequence
  fixtures with a supported state diagram and consume the shared theme target.
- Add a viewer preparation method for exact dimensions, selected appearance,
  cleared selection, and a frozen export view. Fit actual geometry and label
  bounds through the existing frame-point/depth code; avoid a second inspection API.
- Keep CSS framing and drawing-buffer updates atomic, selecting pixel ratio 1
  for export. Reject dimensions beyond the pinned browser's drawing-buffer limits.
- Encode only the renderer canvas. DOM screenshots and image resampling would
  include controls or alter the original pixels.
- Keep static assets generated by Bazel. The website's shared image partial
  selects light/dark raster siblings using its existing image behavior.
- The `isometric` export option uses the diagram's configured 3D direction,
  including the architecture target's shallow front-left perspective.

## Risks / Trade-offs

- Fixed image sizes can make dense labels small: document sizing and retain interactive links.
- Projection affects label placement: iterate fitting and independently check raster borders.
- Preserved code predates core simplifications: extract assigned snapshot paths and adapt viewer integration instead of restoring old core files.
- Browser/font variability: use existing pinned Chrome, SwiftShader, embedded fonts, and image/hash artifacts.
