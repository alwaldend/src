# A79 process checkpoint

## Result-first verdict

Continue A79, but stop expanding the preflight surface.  The next useful
artifact is a mechanically eligible Blender candidate and its fixed-view
pixels, not another broad design document.

The parallel reference, interface, density, selector, build-safety, and render
harness workstreams found real defects early: Variant B was faceted/card-prone,
Variant A v1 copied receiver slices, and the first interface contract required
a closed rear root that would have forced the same rejected shell.  Those are
valuable vetoes.  The same machinery becomes counterproductive if it delays a
candidate after the representation and interface are corrected.

## Process defect found

The closed `105 x 105 mm` rear receiver-root requirement conflicted with the
reference construction and with A79's non-concentricity rule.  A broad rear
felt panel is attached under the crown/bow and supported by overlapping side
layers; it is not glued around its complete perimeter.  Keeping the closed
root would reward a helmet while rejecting the photographed construction.

The revised interface therefore uses an open crown/root course with bounded
upper-side tabs.  Full rear coverage remains a separate object-ID pixel gate.

A second overconstraint was rejected: the density study's large cage sizes are
useful estimates, not mandatory authoring topology.  A dense interpolated cage
adds no form information and is harder to art-direct.  Sparse reference-shaped
controls remain eligible when the applied/frozen surface itself proves the
pixel-span, convergence, thickness, fold, and extrema gates; add local knots
only where a measured feature fails.

## Execution rule for the remainder of A79

1. Freeze the revised literal nets, applied/frozen refinement, and corrected
   root contract.
2. Run one immediate selector re-entry review.  If the representation is
   plausible and the pure mechanical report passes, build it in pinned
   Blender without adding more planning layers.
3. Reject only hard topology/interface failures before rendering.  Judge
   softness, curtain/card read, silhouette, layer order, and likeness from the
   five-view packet, because those are pixel questions.
4. Permit bounded edits to one named panel at a time when the representation
   is sound.  Reset only when pixels expose a representation-level failure.
5. Keep the protected rung and tracked asset immutable until a candidate is
   demonstrably better in every affected view.

This preserves the useful adversarial gates while restoring candidate latency
and visible progress as the optimization target.
