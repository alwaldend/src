# A79 whole-process optimization

## Verdict

The dominant bottleneck was gate ordering, not Blender throughput, compute,
the sandbox, or a lack of parallel workers. A79 took 94 minutes 30 seconds to
produce its first new whole-character pixel; all five 512 px views then
rendered in 29.115 seconds and rejected the representation immediately.

The old loop made promotion-grade contracts, topology proofs, builder
authorization, and schema reconciliation prerequisites for visual feedback.
That was the wrong dependency graph for reference-driven modeling. It also
allowed narrowly scoped `PASS` results to look like model progress even though
no candidate pixels existed.

## Evidence

- `PROCESS_TIMELINE.md` reconstructs A77--A79 and measures the critical path.
- `LOOP_DESIGN.md` defines the replacement DAG, budgets, artifacts, and cache
  boundaries.
- `../diagnostic_preview/a79_non_candidate_five_view.png` is the first actual
  A79 whole-character pixel evidence.
- `../diagnostic_preview/DIAGNOSIS.md` records the categorical visual reset.

The diagnostic preserved the protected rung and tracked asset hashes, used
the pinned Blender, saved only a unique scratch blend, and clean-reopened. It
therefore demonstrates that early pixels and source safety are compatible.

## Process change applied

Future cycles use two distinct lanes:

1. Freeze a bounded complete blockout and run only the checks needed to render
   it safely from an immutable copy.
2. Produce a clearly labelled, non-promotable controlling-view diagnostic by
   12 minutes from cycle start and within 60 seconds of geometry freeze.
3. Reject immediately on bald coverage, helmet/curtain/card reads, broken
   layer order, gaps, or other categorical failures.
4. Run detailed mechanics concurrently after the geometry hash exists, but do
   not block diagnostic pixels on promotion-grade schemas.
5. Freeze interfaces, build the guarded candidate, clean-reopen, render the
   deterministic beauty/semantic packet, and run blind review only for a
   visual survivor.

The coordinator stops workers as soon as their output cannot affect the next
decision. Partial checks publish stage-qualified verdicts; a bare `PASS` is
not used for evidence that does not authorize the requested result.

## Repository skill correction

`projects/goal/skills/goal/SKILL.md` now generalizes this as staged feedback
before promotion: create the smallest safe diagnostic artifact that can
falsify the dominant uncertainty, then escalate validation as the artifact
earns it. A Promptfoo case covers the failure mode. Structural validation,
the offline eval configuration, discovery-link state, and Buildifier all pass.

This does not weaken safety or final acceptance. It changes when expensive
promotion evidence is paid and restores observable result evidence to the
critical path.
