# Reimu Fumo process audit: A69--A72

## Verdict

The four attempts produced useful falsification evidence, but **no visual
progress was promoted into the Fumo**.  A69--A72 all leave the protected rung
003 and the tracked reusable asset unchanged.  A69 and A70 fail criteria
001--004; A71 does not reach an artistic edit; A72's first render is already a
representation reset.  The current canonical goal still lists A72 as open,
although its implementation-blind review says `RESET`.

The rendering loop is not the bottleneck.  A70 generated four five-view
versions in about eight minutes, and A72 went from candidate pixels to an
independent verdict in under three minutes.  The bottleneck is the conversion
of reference evidence into geometry: detailed prose contracts are followed by
ad hoc formulas or a tool probe whose vertices are not driven by the traced
reference silhouettes.

The next attempt should **not** tune A72's exponents or accept an isolated
receiver as meaningful whole-model progress.  Use an editable,
reference-traced per-height profile cage with independent width, front, and
rear controls and broad cap rings.  Derive a minimal visible hair mantle and
rear-leaf proxy from that same rest surface, then judge it in whole-subject
front/profile/three-quarter context with registered reference overlays.  This
is the smallest work unit that tests both the required macro shape and the
repeatedly failing ownership/interface boundary.

A compact visual witness for this audit is
`out/reimu_fumo_process_audit_a69_a72/a69_a72_front_side.jpg`.  Its five rows
show the controlling front/physical-side references followed by A69, A70,
A71, and A72 front/profile renders.

## Root causes

### 1. Reference knowledge exists in prose but does not drive vertices

The durable reference packet and the A69/A70 reports contain useful normalized
targets, view ownership, and construction observations.  The implemented
geometry does not consume sampled reference contours:

- A70 uses `rounded_grid_point()` and `yoke_outer_point()` equations whose
  coefficients are manually guessed.
- A72 uses one vertical superellipse, one section exponent, and a small
  analytic rear taper.
- A69 compares pixel change primarily against the old candidate, which proves
  movement but not reference alignment.

Consequently the geometry is deterministic but generic.  The references
influence the explanation and rejection, not the actual shape construction.
No A69--A72 packet includes a calibrated candidate/reference silhouette
overlay that could turn pixel mismatch into the next control-point movement.

### 2. The module boundary is known to be incompatible, then repeatedly
treated as fixed

A69 showed that moving the head/cap while preserving legacy roots loses
contact.  A70's own reference report explicitly warned that a genuinely
shallower receiver could leave the frozen locks and bow roots floating, while
extending coverage back to those roots recreates the helmet.  It prescribed a
coupled receiver/rear-leaf/root-transfer scope if that happened.

The later attempts instead retreated to a receiver-only object.  That removes
the contact problem from the render rather than solving it.  The receiver is
mostly hidden in the supplied references; its exact form is underdetermined
without the fitted hair mantle and free rear layers that own the visible
silhouette.  A receiver-only score can reject a generic egg, but it cannot
prove the integrated head will resemble the plush.

### 3. Convenient primitives keep substituting for manufactured construction

The sequence is deformation of a helmet, independent extruded cards, an
Icosphere, and a superellipsoid.  Each is easy to script and audit, but none is
derived from the plush's panel ownership and asymmetric side/rear silhouette.
The process is selecting representations that fit the available automation,
then asking visual review whether they happen to look right.  After many
cycles, that is backwards: the reference contour and sewn layer order should
select the control representation.

### 4. Cheap preflight is not consistently applied to the actual formula

A72 could have been rejected before Blender:

- its declared 99 mm total depth is outside its own 101.6--112.2 mm band;
- its formula centers the rear maximum instead of placing it around 0.70 of
  rear height; and
- its plan vetoes a pole pinch while the implementation deliberately closes
  both ends with single poles.

A71's machine probe has the same class of defect.  It counts displacement
above `1e-9 m` and marks the Elastic Grab result as passing when at least 700
vertices changed numerically.  It therefore writes `"pass": true` for a
stroke whose only meaningful support is 40 vertices above 0.1 mm.  The human
review corrected the verdict, but the preflight contract did not encode the
thing it claimed to test.

### 5. Evidence identity and replay are weaker than the written protocol

A71's render manifest identifies
`p0_raw/reimu_fumo_a71_p0_raw.blend` with SHA-256 `f872db...`, but that hash is
now the `.blend1` backup; the current named file hashes `0004a3...`.  The exact
rendered source is recoverable, but the path/hash pair is stale.  A72's packet
contains five candidate renders but no copy or explicit registered comparison
of the controlling references.  A later reviewer can reconstruct context from
the repository, but the packet is not self-contained evidence.

### 6. Strong rejection discipline is not paired with an improving baseline

The reviews are candid and usually stop bad work before detail.  That is a
real process strength.  However, four consecutive resets leave the best whole
model exactly where it started.  The protocol is optimized to avoid false
promotion, but not yet to produce a visually better complete candidate.  The
next unit must therefore be judged both absolutely and against the whole
working rung, with a reversible provisional promotion when it is clearly
better and interface-safe.  Otherwise more excellent postmortems will not
produce the requested plush.

## What improved and what did not

Improved:

- Immutable parent protection, exact hashes, fixed cameras, clean reopen, and
  pinned 5.2.1 renders prevent accidental damage or unsupported promotion.
- Early vetoes work: A69 stopped before C2, A71 stopped before artistic work,
  and A72 received a quick blind rejection.
- The live host plus pinned renderer makes geometry-to-pixels feedback cheap.
- Independent reviews do not confuse operator success with likeness.

Not improved:

- The visible whole-model Fumo remains the same rung-003 asset.
- The dominant head/hair silhouette and manufactured-construction scores stay
  in the 1--5/10 range.
- No attempt binds reference contours directly into control points.
- The head/hair/root interface remains unresolved.
- A70's finding that total depth was already broadly valid has not stopped
  later work from treating total receiver depth as a principal variable.

## Adversarial decision review for the next work unit

### Outcome and constraints

Produce a recognizable, reusable, animatable 25 cm Reimu Fumo matching the
canonical front and turn references.  Preserve the tracked asset until a
candidate passes.  Keep this next unit at macro neutral-sculpt detail: no
materials, fibers, rigging, or unrelated body polish.

### Strongest case for a receiver-only per-height loft

It directly fixes A72's coupled exponent problem, is deterministic, gives
explicit broad support, avoids the broken synthetic brush interface, and can
remove the pole pinch with cap rings.  It is the right low-level mechanism for
creating a controllable rest surface.

### Strongest reason to reject it as the whole A73 outcome

The receiver is not the controlling visible object in most supplied views.
A69/A70 already show that the hair and frozen attachment roots own the failing
silhouette and can force a correct receiver back into a helmet.  Passing an
isolated receiver and postponing that interface can create another technically
clean rung with no usable integrated result.

### Credible alternatives

| Choice | Quality potential | Main risk | Verdict |
| --- | --- | --- | --- |
| Tune A72 exponents | Low | Preserves egg/mattress coupling and pole pinch | Reject |
| Retry synthetic MCP sculpt | Medium in theory | A68/A71 show unreliable broad support; no artistic edit is reached | Reject until the interaction method itself changes |
| Whole-model rebuild | Potentially high | Too many coupled unknowns; destroys the current reference and validation context | Reject for this unit |
| Reference-traced profile cage plus derived minimal hair layers in whole context | High | Requires explicit contour tracing and a widened root interface | **Proceed** |

### Verdict

**Revise** the proposed receiver-only reset.  Keep the independent per-height
profile mechanism, but make it a shared head-rest-surface control and require a
minimal integrated visible layer test before the attempt can count as a
successful rung.

## One high-leverage next work unit

### A73: reference-traced head profile cage and visible-layer coupon

1. **Trace before Blender.**  From the canonical front and selected canonical
   turn profile/rear frames, record 7--9 normalized height stations.  At each
   station store independent half-width, front reach, receiver rear reach, and
   visible brown rear reach.  Record the image pixels, camera registration,
   uncertainty, and source frame that owns each value.  Do not derive these
   from A72.
2. **Run a static formula preflight.**  Reject the table before geometry if
   width/height/depth bands fail, rear maximum is not near the source's upper
   mid-height, lower rear does not move forward by 0.05--0.08 Wh, either end
   collapses to one pole, or any profile reverses unexpectedly.
3. **Build one editable low-density cage.**  Loft the stations through
   independently controlled front/rear/width rings with 2--3 tightening crown
   and underside rings.  Use smooth interpolation only between measured
   stations.  Keep the cage as the reusable macro control rather than baking
   another opaque formula primitive.
4. **Derive the smallest visible construction test.**  Generate the beige
   receiver and a close-fitted brown crown/temple mantle from the same cage,
   plus simple separate lower rear-leaf proxies.  Move their root bands
   surface-relatively; do not preserve incompatible legacy root coordinates
   and do not build a bridge to reach them.  Preserve the old model only as
   reversible comparison context.
5. **Render two gates, not one isolated beauty packet.**  First render the
   receiver alone as a cheap shape veto.  If it survives, immediately render
   the minimal head assembly in the full rung-003 subject context from front,
   both profiles, rear, and both three-quarter cameras.
6. **Produce registered evidence automatically.**  Every controlling view
   needs the source beside it and a 30--50% silhouette overlay/edge difference,
   bound to the exact candidate hash.  Attach the controlling reference paths
   and hashes to the packet.
7. **Pass only on visible result.**  Require no egg, mattress, helmet, card,
   pole pinch, bald gap, floating root, or exposed bridge; critical contour
   errors within 0.05 Wh; macro silhouette at least 6/10; constructed-plush
   read at least 5/10; and a whole-subject A/B preference over rung 003 with no
   front identity regression.  If the receiver passes alone but the visible
   assembly fails, reset the module boundary rather than promoting the
   receiver.

This work unit is still small: it changes only the head rest surface and
minimum layer ownership needed to expose the known interface failure.  It
prioritizes a viewable model improvement while deferring hair detail, bow
construction, body, materials, and rigging.

## Process changes that should be retained

- Keep one canonical `.blend` writer and parallelize reference tracing,
  deterministic preflight, blind review, and evidence assembly.
- Make the static preflight consume the same parameter table as the Blender
  builder, so prose and geometry cannot silently diverge.
- Define material motion thresholds and support spans, not floating-point
  coordinate change, in every tool gate.
- Save immutable candidate bytes before rendering and never rewrite the source
  path named in a manifest; write a new checkpoint directory for every rerun.
- Include the controlling reference images or stable repository-relative paths
  and hashes in every review packet.
- Preserve quick 320 px vetoes and pinned 5.2.1 verification.  Do not spend
  time optimizing render startup, Bazel, hashing, materials, or microdetail;
  none is currently limiting visual progress.
