# Historical project-agents delta

These requirements describe the archived change at its recorded acceptance point. They were imported without applying them to the current `project-agents` baseline. Current source and baseline requirements own present behavior.

## ADDED Requirements

### Requirement: Single-owner agent-system architecture

The repository architecture MUST define the links from intent and topology through policy, capabilities, work, execution, evidence, delivery, and learning while keeping mutation authority at each fact owner.

#### Scenario: A system-wide view joins component facts

- **WHEN** a derived catalog or document combines multiple owners
- **THEN** it retains provenance, freshness, conflicts, unavailable fields, and truncation instead of creating a parallel mutable authority

### Requirement: Observed state and proposed work separation

Current-state evidence MUST remain distinct from normative architecture and a dependency-ordered roadmap with measurable acceptance and cost controls.

#### Scenario: A roadmap phase is proposed

- **WHEN** a reader follows the repository entry point to future work
- **THEN** the documentation identifies the phase as proposed and does not present its interfaces as implemented guarantees

### Requirement: Direct entry and reviewed learning

Root agent and human entry points MUST link directly to canonical system documents, and maintained learning MUST trace observation to regression and an owner-reviewed change without weakening authority boundaries.

#### Scenario: A new agent enters at the repository root

- **WHEN** the agent needs system context or the current work-to-learning route
- **THEN** the entry points identify the canonical documents and the sequence preserves evidence and ownership identities
