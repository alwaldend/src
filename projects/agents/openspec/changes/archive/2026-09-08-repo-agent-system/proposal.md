# Make the repository a coherent, agent-intuitive, agent-ergonomic, and agent-accretive system

## Why

The original repository-wide audit found fragmented entry points and unclear joins between agent policy, execution, evidence, delivery, and learning. The achieved design phase made those boundaries legible while retaining each fact at its natural owner.

This change was imported as completed historical work on 2026-09-08. The source outcome is `achieved` and execution is `paused`. Checked tasks reproduce its accepted review; they are not a new validation of current code. Historical deltas were not applied to the independently documented current baseline.

## What Changes

- Thin composition with one fact owner: The architecture connects owner-local facts through typed contracts, stable references, and bounded deterministic projections. It rejected a second mutable central registry, mega-skill, mandatory daemon, transcript store, and physical reorganization for navigation alone.
- Separate observation, contract, and intent: Current-state documentation records a revision-bound evidence baseline. Architecture describes the composition contract. The roadmap orders proposed work and does not assert that later phases already exist.
- One-hop entry and closed learning: Root policy and README route to canonical documents. The work loop runs from orientation and binding through planning, admission, execution, evidence, and decision, followed by delivery or a justified stop; learning becomes a minimized regression and an owner-reviewed change.
- Content-based information handling: Secrets and personal information never become public durable evidence. Non-secret operational facts are not automatically confidential. Temporary secret-bearing artifacts require task-private ignored storage and cleanup; old audit proposals are retained as history, not present policy.
