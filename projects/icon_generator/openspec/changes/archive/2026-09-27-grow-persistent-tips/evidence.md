# Persistent tips acceptance

The user approved persistent growing tips as a fourth algorithm, relaxing the
paired-child rule only for this selection. Compact remains default. No new
external dependency or host installation was needed.

## Behavioral verification

- Command E2E cases were written first. The initial run failed because the CLI
  rejected `tips`; the implementation then passed the complete project suite.
- E2E checks cover connected descent from sampled roots, retention of root
  colors, sparse extended growth, replay, replication-option isolation,
  single-child extension, and narrow/clipped/empty/full canvases.
- All nine E2E example commands replay with identical decoded checksums and PNG
  bytes. The eight preexisting examples remain byte-identical.
- The forced disk-write failure check remains unchanged and passes.
- The OpenSpec delta passes strict validation.

## Visual verification

Ten 1024 by 1024 comparisons use white 1-pixel squares on #212121, seed 5333116260189394413. Every PNG was decoded to verify dimensions and exact palette
and regenerated byte-for-byte. Full-size inspection of variants 4 and 10 shows
long curved stems, shorter offshoots, and open gaps. The denser variant forms a
more interwoven texture; organic appearance remains a visual preference rather
than a test guarantee.

## Maximum canvas

4096-square, size 1, tips, factor 1, seed 42, white on #212121:

- Density 0.0002: 622,099 occupied cells; 0.90 seconds, peak 86,080 KiB.
- Density 0.9: 15,100,401 occupied cells; 3.97 seconds, peak 145,088 KiB.

These are observed local timings, not performance guarantees. Both outputs
were decoded and checked for dimensions and palette.
