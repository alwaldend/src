# Verification: delivery

Use the [verification protocol](README.md) and the pinned source snapshot.
The rebase and selected-base rows cite the R1/R2 fixture passes in the [protocol](README.md);
other results remain unrun for this documentation pass. Fixture observations are
automated evidence, not a manual production or interactive-terminal pass.

For a named test, run from the `projects/al` workspace with
`bazel test //internal/delivery:go_test
--test_arg=-test.run=^TEST_NAME$ --test_output=all`, replacing `TEST_NAME` with the
exact name in the row. Keep the test log and any undeclared output artifact under
the pass evidence directory. Read the named fixture before running it so its
assertions, controlled environment, and coverage limits are clear. Do not infer
that a passing fixture exercised live GitHub timing.

Rows labeled **instrumented fixture** require a disposable Git/forge setup with
the stated pause or failure hook. Existing tests provide its reference behavior,
but these rows are blocked until that setup exists; do not substitute the real
repository or forge. TTY rows require a controlling terminal. No row authorizes
a live push, review comment, or credential change.

## Not checkable by hand

- Check selection and adequacy remain the operator's responsibility. AL does not
  inspect ordinary Bazel results; successful publication is not evidence that
  tests ran or passed.

- A finite pass cannot prove absence of all GitHub-side races or moderation
  events omitted from its bounded projection. The documented boundary is a
  limitation, not a claim to be certified by one successful mutation.
- Unimplemented pause/failure hooks above are verification setup work, not
  product defects. Record those rows as blocked when attempting a pass without
  the required setup; do not mark them passed from source reading.
