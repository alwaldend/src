# Verification: configuration, command execution, and diagnostics

Use the [verification protocol](README.md) and the single source snapshot in the
[scope decisions](../README.md#scope-decisions). These are scripted observations
and unperformed checks, not a completed manual pass. All three feature documents
remain `drafted`.

## Fixture conventions

- **AL:** the source-built installed executable, selected by its absolute path.
  Run each case with a fresh directory under ignored `out/<task>/<case>`.
- **Clean environment:** preserve only `PATH` pointing to private fixture
  executables followed by `/usr/bin:/bin`, `LANG=C.UTF-8`, a task-private
  `TMPDIR`, and explicitly named fixture variables. Do not inherit credentials.
- **R:** the same setup with `RUNFILES_DIR` pointing to an empty case-local
  directory. C1 used this setup to exercise execution beyond the original B-01;
  it does not substitute for the separate binary-only installed cases.
- **Merge inputs:** `first.json` contains a plugin named `first` with a
  nonexistent executable and label `fixture=first`; `second.yaml` contains a
  plugin named `second`; `third.lua` calls `config` with a plugin named `third`.
  Do not select these plugins for execution.
- **Gate configuration:** a trusted case-local Lua file writes a `ready` marker,
  then loops until a case-local `continue` file exists, then calls `config({})`.
  Use this only to interrupt setup or change a later input before it is loaded.
  Bound every experiment to 20 seconds and signal only its recorded process ID.
- **Waiting child:** a case-local Python program writes `ready`, registers a
  SIGTERM handler that writes `stopped` and exits, then waits. A separate variant
  deliberately ignores SIGTERM. No child contacts a service or reads real secrets.
- **Bazel fixture:** a private executable named `bazel` records whether it was
  invoked. Put its directory first on PATH to check doctor path resolution and
  that diagnostic reporting does not launch Bazel. No real build is needed.
- **Doctor workspace:** use a case-local `.bazeliskrc` with the repository's
  declared pin fields when testing failures or changes. Ordinary observations
  can read the repository workspace. Never alter its actual pin file.
- **Controlled doctor read:** use a FIFO named `.bazeliskrc` only inside a
  disposable doctor workspace. Its local writer opens the FIFO, records
  readiness, waits for a case-local gate, then writes the pin fields and closes
  it. Record both process IDs; terminate only these fixture processes afterward.
- **TTY:** observe a foreground command in a disposable terminal. For hangup,
  close only that terminal and inspect case-local files from another terminal.
  Broken-pipe and forced-kill cases use a local parent process and its recorded
  children; do not signal unrelated processes.
- **Timing:** if an invocation finishes before an intended interrupt, mark that
  case `blocked` or retry with a newly recorded controlled fixture. A signal sent
  after completion is not evidence that interruption was exercised.
- **Failure injection:** use a disposable unprivileged fixture account or an
  already available isolated filesystem for inaccessible/full-file cases.
  If unavailable, record `blocked`; never fill or remount a host filesystem.
- **Plugin fixture:** the repository's existing synthetic injector scenario in
  `tools/al/test/command/command_test.go`; no live Vault or real credentials.
