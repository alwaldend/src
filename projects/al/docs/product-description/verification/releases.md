# Verification: releases

Use only the isolated setups in [the protocol](README.md). `AL` is an absolute
binary path. Define `GEN` as `AL release generate --project projects/example
--version_file STATUS --add_file PAYLOAD --output_dir OUTPUT`, replacing uppercase
paths with absolute scratch paths. A development `STATUS` contains
`STABLE_VERSION 0.0.0-dev` and `STABLE_VERSION_CHANNEL development`; a release
status comes from the isolated Git fixture's `version bazel-status` output.

`PUB` means the fixture's `AL release publish --release_dir BUNDLE --environment
local --ssh_host FIXTURE --ssh_root ROOT` with the fixture SSH/rsync executables
and trust inputs. ROOT is disposable fixture content, never a live host. Use a
fresh receipt path for each attempt. Existing fixtures own transport setup;
reuse them rather than weakening host trust. `EXTRACT` and `ACTIVATE` use those
same fixture selectors with `AL release website extract` and
`AL release website activate`; only EXTRACT accepts `--site_archive`.

`PLAN` and `INSPECT` use those same fixture selectors with `release plan` and
`release inspect`. Planning is an offline metadata preview; inspection reads the
fixture's current state. Neither authorizes a publication. Preserve the original
scripted observations when adding later fixture results.

Later planning/inspection rows cite **O1**, the complete release-package fixture
pass recorded in the [protocol](README.md#later-fixture-passes). Its numbered JSON
reports are retained under `out/unify-release-versioning/release-observation/final-evidence/`.
The fixture uses the built CLI, synthetic payloads, and controlled SSH transport;
it is not a live-destination or manual-terminal pass. **W1** records the later
nested website-command fixtures, with current preview reports under
`out/unify-release-versioning/api-naming/website-evidence/`. Earlier observations
retain their original command surface. Unrecorded rows remain `—`.

## Versioning

VER-04, VER-13, and VER-26 are retired with create-time checkout; VER-24 is
retired with the stamped-build wrapper. Those IDs remain reserved. Ordinary
Bazel stamping is covered by VER-45–47; release creation and explicit checkout
are covered by VER-48–49.

`VER` below means `AL version --repository REPOSITORY`, with an absolute path to
a fresh synthetic Git checkout under task scratch. Initialize it with clean
trunk, one ordinary payload commit, and a local bare origin whose trunk points
to that commit. The fixed example date is `2026-11-02`; it makes the sample
identity reproducible. `PLAN` and `RECEIPT` are absolute task-scratch paths.
`CREATE` means `AL release create --repository REPOSITORY`. A prepared weekly
fixture has run CREATE and then `git -C REPOSITORY checkout releases/2026.45`;
creation alone leaves the selected branch unchanged.
Never point these preparation or publication commands at the real repository.

The scripted results name observations from the local-bare-remote pass recorded
on 2026-11-02 in `observations-release/observations.json`. They do not claim live
SSH authentication or interactive-terminal coverage. Interrupt rows need
controlled pause/failure hooks in a disposable process or remote; mark them
blocked if the setup is unavailable.
