## Supersession and conflict decisions

- Anki application baselines use the current `col/config/api/server` command groups,
  injected client factories and collection-source API. The old `cli-scaffold`
  placeholder commands and `collection-workflow` manager model remain historical.
  Current requirements preserve managed and borrowed ownership, optional state
  output, native publication on handled failures, and immutable source text.
- The old shared runtime `App` model is superseded by the pure client factory.
  Factory construction has one current owner in `client-connection-delegation`.
  Twelve surviving scenarios were moved to their current capability owners rather
  than discarded when overlapping `collection-text` requirements were deduplicated.
- Anki transport baselines normalize old constructors and mandatory worker assumptions
  to current `ClientSTD`, explicit executable ownership, native and WASM engines.
  `backend-managers` remains historical. Worker registration, per-factory isolation,
  scoped IPv6 routing and raw callback lifetime have one current owner in
  `client-connection-platforms`. Archive preservation without `WriteBack` is distinct
  from the later opt-in publication contract.
- Repository-level `add-anki-cargo-go-api` no longer defines `pkg/backend`,
  `BackendSTD`, or a blanket prohibition on C ABI. Surviving generated RPC/error
  and native-lifetime guarantees live under `projects/anki_grpc/explicit-backends`.
  `extract-anki-grpc-project` transport guarantees live in `linked-server`, using
  the current `serve` subcommand. The obsolete repository deltas remain historical.
- Repository policy replaces the obsolete transitional goal-tool deprecation
  contract with its implemented removal, preserving single-authority routing,
  isolated workspace and project-owned skill requirements.
- `tools/rules_skills/external-skill-materialization` had stale proposal/delta names
  (`skill_materialization` and `write_source_files`) that contradicted its accepted
  design and implementation. Those artifacts now consistently name `skills_write`.
  Its design records this reconciliation; existing discovery guarantees are retained.
- Site, Mermaid and host changes merge only their named requirements and preserve
  unrelated scenarios. The X Article payload delta was already reflected exactly
  in the baseline and required no repeated specification edit.
